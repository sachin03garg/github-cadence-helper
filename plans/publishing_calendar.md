# Publishing Calendar

The goal is not to look busy. The goal is to make your public work look like a thoughtful technical buildout over time.

## Weeks 1-2

- Create profile README
- Rewrite `serverless-rag-demo` README
- Add repo descriptions, topics, and pinning order notes
- Push the initial scaffolds without over-polishing them

## Weeks 3-4

- Expand the synthetic instruction dataset
- Add dataset-formatting notebook commentary
- Commit prompt-only baseline notes
- Open issues for LoRA and eval follow-ups

## Weeks 5-6

- Deepen the LoRA SFT notebook
- Publish first benchmark note
- Add one real failure-analysis section
- Improve config docs around rank, alpha, and target modules

## Weeks 7-8

- Add the QLoRA tradeoff notebook
- Publish adapter merge/unmerge inference notes
- Compare prompt-only vs tuned behavior on structured outputs

## Weeks 9-10

- Publish golden set and regression cases
- Add release-gate logic to the eval repo
- Improve benchmark reporting language and tables

## Weeks 11-12

- Publish latency / throughput benchmark report
- Add blind spots and benchmark methodology notes
- Add one small follow-up commit instead of a large batch push

## Weeks 13-14

- Add voice-agent architecture and control loop
- Add mock tool data and demo session script
- Open issues for fallback, traces, and handoff behavior

## Weeks 15-16

- Add fallback paths, trace examples, and runbook
- Add latency budget notes and operational checkpoints
- Polish repo READMEs based on what now feels thin

## Weeks 17-18

- Capture screenshots, demos, and issue closures
- Tighten wording, diagrams, and benchmark notes
- Refresh pinned repos if another project becomes visibly stronger
- Write one short public note tying together PEFT, evals, and deployment thinking
